# 🔍 技术尽职调查报告: yukiyokotani/office-open-xml-viewer

## 1. 项目速览 (Executive Summary)

> 一个基于浏览器的 Office Open XML（PPTX/XLSX/DOCX）文档查看器，将文档渲染为 HTML Canvas，但当前处于早期概念验证阶段，功能尚不完整。

## 2. 深度审计详情 (Deep Dive)

### 2.1 架构设计与代码质量 (Architecture & Code Quality)

#### 架构模式和设计理念
- **单体库 + 模块化文件结构**：项目未采用 monorepo 或插件化架构，而是将所有文件放在 `src/` 下，按文档类型（pptx, xlsx, docx）划分子目录。
- **渲染引擎**：核心思路是解析 OOXML 的 XML 结构，通过 Canvas 2D API 逐层绘制。未依赖第三方渲染库（如 Fabric.js、Konva），而是直接操作原生 Canvas。
- **数据流**：使用 `fetch` 加载文件 → `JSZip` 解压 → `xml2js` 解析 XML → 内部对象模型 → Canvas 渲染。

#### 技术选型
- **语言**：TypeScript（严格模式），类型定义基本完整。
- **构建**：Rollup（配置在 `rollup.config.js`），输出 UMD/ESM 格式。
- **依赖**：`jszip`（解压）、`xml2js`（XML 解析），无大型 UI 框架依赖。
- **测试**：无测试框架配置，未发现任何测试文件。

#### 亮点 (Pros) ⭐
1. **零外部渲染依赖**：直接使用原生 Canvas API，没有引入 Fabric.js 等重量级库，包体积控制潜力大。
2. **类型安全**：TypeScript 严格模式启用，`tsconfig.json` 中 `strict: true`，对内部数据结构有较完整的类型定义，降低了运行时类型错误。

#### 改进点/缺陷 (Cons) ⚠️
1. **缺乏抽象层**：PPTX、XLSX、DOCX 的解析和渲染逻辑高度耦合，没有统一的 `DocumentParser` 或 `Renderer` 接口。例如 `src/pptx/` 和 `src/xlsx/` 的代码几乎完全独立，难以扩展支持新格式。
2. **性能隐患**：所有渲染逻辑在主线程同步执行，没有使用 `OffscreenCanvas` 或 Web Worker。对于大文件（如 100+ 页的 PPTX），可能导致明显的 UI 卡顿。
3. **错误处理薄弱**：`try/catch` 使用极少，例如在 `src/pptx/parser.ts` 中，如果 XML 结构不符合预期，会直接抛出未处理的异常。

### 2.5 创新性与价值 (Innovation & Value)

#### 解决的核心痛点
- 在浏览器中无需安装 Office 软件即可预览 `.pptx`、`.xlsx`、`.docx` 文件，且输出为 Canvas（便于截图、水印、二次编辑）。

#### 与同类库对比优势
| 对比维度 | office-open-xml-viewer | Office.js (Microsoft) | pptxjs | SheetJS |
|---------|----------------------|----------------------|--------|---------|
| 渲染方式 | Canvas | DOM | DOM | 表格数据 |
| 支持格式 | PPTX+XLSX+DOCX | 全格式 | 仅PPTX | 仅XLSX |
| 体积 | 较小（无UI框架） | 极大（需加载Office Online） | 中等 | 中等 |
| 浏览器兼容 | 未知 | 仅Edge/Chrome | 良好 | 良好 |

- **核心优势**：Canvas 渲染使输出更可控，适合需要定制 UI 的场景（如在线教育平台、企业文档管理系统）。
- **核心劣势**：功能完整性远低于竞品，例如无法渲染 PPTX 的动画、Excel 的图表、Word 的页眉页脚。

#### 亮点和改进点
- ✅ **亮点**：选择 Canvas 而非 DOM 渲染是差异化策略，技术路线有潜力。
- ❌ **改进点**：
  - **功能严重缺失**：仅支持最基本的文本和形状渲染，无法处理：
    - PPTX：图表、SmartArt、母版、动画
    - XLSX：公式、条件格式、数据验证
    - DOCX：表格、图片、页眉页脚
  - **文档价值有限**：当前状态仅适合展示简单的演示文稿或表格，无法作为生产环境工具。

## 4. 最终裁决 (Final Verdict)

### 总分：28 / 100

### 结论性评价
该项目是一个**有技术思路但未完成的概念验证（PoC）**。作者选择 Canvas 作为渲染目标是一个值得关注的技术方向，但当前代码质量、工程化水平和维护状态均无法支持任何生产环境使用。与成熟的竞品（如 Office Online、OnlyOffice、LibreOffice Online）相比，功能完整性差距巨大。

### 适用场景推荐
- ❌ **不推荐** 用于任何商业或生产环境。
- ⚠️ **仅适合** 以下场景：
  1. 学习 OOXML 解析和 Canvas 渲染的参考代码。
  2. 作为 Fork 起点，在此基础上进行二次开发。
  3. 极低要求的内部原型验证。

### 风险提示
1. **维护风险**：项目已停止维护，无社区支持，遇到问题需自行修复。
2. **功能风险**：大量 OOXML 特性未实现，渲染结果可能严重偏离预期。
3. **兼容性风险**：未测试浏览器兼容性，可能在 Safari 或移动端出现渲染异常。
4. **安全风险**：无依赖审查，`xml2js` 和 `jszip` 可能存在已知漏洞。
